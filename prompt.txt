# 1. Main Concept

The GitHub repository will contain folders and files.

The website should represent the repository structure visually.

### Important rule:

**Every folder should automatically be treated as a Category.**

**Every file inside a folder should automatically be treated as an Item belonging to that Category.**

For example:

```text
repository/
│
├── images/
│   ├── users/
│   │   ├── user-01.jpg
│   │   └── user-02.jpg
│   │
│   ├── products/
│   │   ├── product-01.jpg
│   │   └── product-02.png
│   │
│   └── banners/
│       └── banner-01.jpg
│
├── documents/
│   ├── pdf/
│   │   ├── example-01.pdf
│   │   └── example-02.pdf
│   │
│   └── word/
│       └── document-01.docx
│
├── videos/
│   └── demo.mp4

└── audio/
    └── sample.mp3
```

The website should interpret this structure as:


# 4. Static GitHub Pages Limitation

The website must work with static hosting.

There is no backend.

Because a normal GitHub Pages website cannot directly scan the server filesystem using browser JavaScript, implement a practical solution.

Use a generated metadata/index file such as:

```text
assets.json
```

This JSON file should describe the repository structure.

Example:

```json
{
  "categories": [
    {
      "name": "Images",
      "path": "images",
      "children": [
        {
          "name": "Users",
          "path": "images/users",
          "children": [],
          "files": [
            {
              "name": "user-01.jpg",
              "path": "images/users/user-01.jpg",
              "type": "image"
            }
          ]
        }
      ]
    }
  ]
}
```

The frontend should load:

```javascript
fetch("./assets.json")
```

and dynamically generate the entire UI.

---

# 5. Automatic assets.json generation

Also create a simple GitHub Actions workflow that automatically scans the repository and regenerates `assets.json` whenever files/folders are added or removed.

The workflow should:

1. Run on every push to `main`.
2. Scan the repository.
3. Ignore:

   * `.git`
   * `.github`
   * `index.html`
   * `assets.json`
   * workflow files
   * unnecessary project files
4. Detect all folders.
5. Detect all files.
6. Determine file types.
7. Generate `assets.json`.
8. Commit the generated `assets.json` back to the repository if it changed.
9. Allow GitHub Pages to serve the updated website.

Use a simple approach that does not require a complex application.



```javascript

```

and DOM APIs.

Do NOT depend on external icon libraries such as:

* Bootstrap Icons
* Material Icons
* Lucide CDN
* Heroicons CDN

The application must work completely offline after the repository is loaded.

Create a reusable SVG icon system in Vanilla JavaScript.

For example:

```javascript
const icons = {
    folder: `<svg ...>...</svg>`,
    image: `<svg ...>...</svg>`,
```
